## 三、备案信息展示（已实现）

**要求**：主页底部中央标明网站备案编号，并在编号下方链接备案管理系统。

**实现**：

- `src/client/components/SiteFooter.tsx`：页脚居中展示 `SITE_ICP_NUMBER` 的备案号，整串数字链接到 `https://beian.miit.gov.cn/`；下方依次为公安备案（取得后显示）、版权行、联系邮箱。
- `src/client/components/PasswordGate.tsx`：站点为邀请制，未登录用户首先看到登录框，因此备案号、四个合规页面链接同步展示在登录卡片底部，保证“主页可见”。
- `public/legal/*.html`：四个合规页面页脚同样展示备案号，且**无需登录**即可访问（服务端直接渲染，不经过前端路由与鉴权）。
- 备案号不写进仓库：`src/shared/site.ts` 只定义字段，服务端 `/site-info.js` 从环境变量注入；静态合规页由 `src/server/index.ts` 的 `renderLegalPage()` 在响应时替换 `%%ICP%%` 等占位符。

**配置**（服务器 `/var/www/translation-training/.env`）：

```dotenv
SITE_ICP_NUMBER=你的网站备案号
SITE_ICP_URL=https://beian.miit.gov.cn/
SITE_OPERATOR=备案主体名称
SITE_CONTACT_EMAIL=你的常用邮箱
```

> 若备案系统中显示的网站备案号为 `湘ICP备********号-1` 形式，请以备案系统为准补全后缀；页脚展示的必须是**网站备案号**而非主体备案号。

## 四、内容合规（“九不准”）

### 4.1 站内内容审查结论

- 题库为 2002–2026 年考研英语（一）翻译真题，属公开试题；短文题材为科普、教育、历史、社会议题，未发现涉及危害国家安全、民族宗教、淫秽色情等禁止内容。
- 站内不存在公开论坛、评论区、弹幕、私信等公开信息发布功能；用户可被他人看到的文本仅有**对战昵称**与**对战中的译文**（仅房间内可见）。
- 因此内容风险主要集中在：昵称、AI 生成文本、题库版权。

### 4.2 已实现的处置

| 措施 | 位置 |
| --- | --- |
| 昵称敏感词与格式审查（注册、改名、PVP 建房/加入/观战全链路） | `src/server/moderation.ts`、`src/server/pvpManager.ts` |
| 禁止冒充官方/客服/管理员、代考、押题、广告导流、联系方式、网址 | 同上 |
| 服务端强制校验，绕过前端直接发 WebSocket 也会被替换为兜底昵称 | `pvpManager.safeNickname()` |
| AI 输出中的 `<script>`、`javascript:` 等危险片段清洗 | `moderation.softenUnsafeOutput()` |
| 违法信息举报页面（范围、渠道、时限、12377/12321） | `public/legal/report.html` |
| 侵权通知—删除机制（24 小时初核、7 个工作日反馈） | `public/legal/copyright.html` |
| 非官方声明、真题来源标注、合理使用范围 | 首页提示条、`copyright.html`、页脚 |

> `moderation.ts` 内置词表只覆盖“冒充、代考、广告、辱骂、低俗、枪支毒品”等通用类别。**政治类敏感词不写入公开仓库**，请通过服务器环境变量 `NICKNAME_BLOCKLIST_FILE` 指向一个仅存在于服务器的词表文件（每行一个词，`#` 开头为注释），并在词表更新后重启服务。

### 4.3 发现违法信息时的处置流程

1. 立即下架/屏蔽相关内容（昵称可强制重置，房间可解散）；
2. 保存访问日志、账号信息、内容快照（不少于 6 个月）；
3. 24 小时内向属地网信办/公安网安报告；
4. 在举报页面记录处置结果并反馈举报人。

## 五、个人信息保护

### 5.1 信息清单（与隐私政策一致）

| 类型 | 内容 | 去向 |
| --- | --- | --- |
| 账号 | 用户名、scrypt 加盐哈希、昵称、注册/登录时间、协议版本 | 本站 SQLite |
| 学习记录 | 译文、年份、方向、得分、采分点、AI 点评、时长 | 本站 SQLite |
| 对战 | 房间号、对手昵称、比分、观战票据 | 内存 + 本站 SQLite（历史） |
| 日志 | IP、UA、路径、状态、耗时 | journald + nginx access.log |
| 本地 | 登录令牌、主题、昵称、草稿、观战标识 | 浏览器 localStorage/sessionStorage |

### 5.2 已实现的控制点

- **告知同意**：注册页必须主动勾选《用户协议》《隐私政策》，未勾选时提交按钮禁用，服务端同样强制校验 `agreedTerms === true`，并记录 `terms_version` 与同意时间。
- **最小必要**：不收集手机号、身份证、位置、人脸；密码只存哈希。
- **委托处理披露**：隐私政策列明评分时向深度求索（DeepSeek）API 发送原句、参考译文与用户译文，仅用于生成评分。
- **权利实现**：`GET /api/user/export` 导出 JSON；`DELETE /api/user/account` 验密后级联删除；历史记录可单条/全部删除。
- **自动化决策**：评分仅用于学习反馈，页面标注 AI 生成，提供复核渠道，不产生重大影响。
- **留存期限**：账号数据存续期间保存，注销后 30 日内删除/匿名化；日志不少于 6 个月。
- **安全措施**：全站 HTTPS、scrypt、CORS 白名单、登录/注册/评分限流、安全响应头、数据库仅本机监听。

### 5.3 待补

- **个人信息保护影响评估（PIA）**：委托处理 + 自动化决策场景，建议按《个人信息保护法》第 55 条完成一份书面评估并留存备查（模板可自行编写，重点写：处理必要性、对个人的影响、风险与缓解措施）。
- **数据泄露应急预案**：建议成文，明确发现、上报、通知用户、补救的时限与责任人。

## 六、生成式人工智能与实名制

### 6.1 AI 标识（已实现）

- 评分卡标题旁固定展示红色「AI 生成」标签，点评末尾附免责说明（`src/client/components/GradingCard.tsx`）。
- PVP 横向对比裁决标注「AI 生成」。
- 评分接口响应头附加 `X-AI-Generated: true`、`X-AI-Model: deepseek`，响应体含 `aiGenerated` 与 `aiNotice`。
- 用户协议第六条、版权声明第六条均说明 AI 生成性质与局限。

> 《人工智能生成合成内容标识办法》自 2025-09-01 施行。文本场景以“适当位置文字提示”作为显式标识即可；若后续提供图片/音频生成或允许下载文件，需补充隐式标识（元数据）。

### 6.2 生成式 AI 备案/登记（待核实）

本站通过 DeepSeek API 向公众提供文本生成（评分点评）。是否属于《生成式人工智能服务管理暂行办法》第 17 条“具有舆论属性或者社会动员能力”的情形，实践中由属地网信办认定。建议：

1. 向**湖南省网信办**（或备案主体所在地网信办）咨询“调用已备案大模型 API 的垂直应用”应办理**备案**还是**登记**；
2. 准备材料：服务说明、模型来源与已备案编号、内容安全制度、违法信息处置流程、个人信息保护措施；
3. 取得备案/登记编号后，在页脚一并展示。

### 6.3 账号实名（风险项）

《网络安全法》第 24 条要求网络运营者为用户办理网络接入、域名注册、固定电话、移动电话，或者为用户提供信息发布、即时通讯等服务时，进行真实身份信息认证。本站为邀请制、无公开信息发布功能，风险相对较低，但监管核查时仍可能被问及。可选加固：

- 邀请码与具体用户绑定发放，保留发放记录；
- 增加手机号/微信扫码登录（需接入合规的实名核验渠道）；
- 在用户协议中明确账号仅限本人使用。
